# 30 天发布与传播计划

这是一份执行计划，不是流量预测。目标不是先凑到某个 Star 数，而是确认陌生用户能跑通、
会复用，并愿意指出真实家庭建模的缺口。全程不买 Star、不刷下载、不批量骚扰、不伪造用户反馈。

## 定位与第一批人

首要人群：自己管理家庭资产、收入中含经营分配/不稳定收入、同时愿意使用本地 Agent 的开发者和技术创业者。
第二人群：对资产管理工作流和可验证计算感兴趣的 FinTech / Applied AI 工程师。
暂不以普通家庭“大众理财 App”、持牌顾问替代品或机构级 Family Office 系统作宣传。

主信息：**Your portfolio is not your whole financial life.**
三个内容支点：资产多但现金不足；出售企业不等于永远增加收入；相同净资产、不同收入结构意味着不同约束。
所有数值展示使用包内虚构数据。不要发收益承诺或“AI 找到最优投资”之类宣传。

## 第 1 周：验收与小范围试用

D1：运行本地验收；核实工作名、MIT 许可、公开边界；用发布脚本建立待验收仓库。
D2：在自己实际使用的 Agent 内跑 `evals/runtime-acceptance.md`，记录宿主/模型/日期，修复失败点。
D3：选 3–5 位愿意试用的人，发 `OUTREACH.md` 的简短邀请；明确只需使用虚构案例，不索要财务资料。
D4：让对方独立从 README 开始，记录卡住的步骤、耗时和错误。不要替他完成后记作成功。
D5：修复最重复的障碍，收敛到“一条命令 + 一个浏览器演示”。
D6：用 `DEMO-SCRIPT.md` 录 60–90 秒视频；录制前清除真实账号名、路径和聊天记录。
D7：远程 CI、公开页面和安装命令实际验证后，发布 v0.2.0；准备欢迎 Discussion。

内部目标假设：5 次自愿试用中至少 3 次独立跑通。如果没有达到，先修复 onboarding，不扩大曝光。
这是项目验收门槛，不是行业转化率基准，也不代表已拿到用户。

## 第 2 周：首发，聚焦一个可理解的问题

D8：LinkedIn 发个人背景 + 业务问题 + 真实演示。主 CTA 是试用并指出遗漏，不是单纯求 Star。
D9：逐条回复实质问题，整理进入 Issue；把重复问题补回 README/FAQ。
D10：X 发短帖与 3–4 段 thread，突出出售企业案例与数字校验。没有受众也不刷屏。
D11：选择一个允许自荐、且与 agent skills 或个人财务软件相关的社区。发帖前核对当前规则。
D12：写一篇技术拆解：为什么 LLM 不算钱、养老金为什么不是新资产类、企业出售如何避免重复计数。
D13：把最有价值的真实失败例子匿名重构为虚构测试，取得引用许可才引用用户原话。
D14：复盘：访问→运行→完成→再次使用。只有点击/Star，没有完成事件，不视为需求成立。

## 第 3 周：建立可信度和贡献入口

D15：发布一份具体 bug/模型边界修复说明，不发布虚假的“爆火”。
D16：开放一个明确的小任务，例如新增虚构场景或运行兼容性报告。不要把架构大改标作 good first issue。
D17：发“同样资产、不同现金流”的第二段演示，避免重复贴同一条发布公告。
D18：准备 Show HN。官方强调应是可以试用的作品，而不是只有预热页；本地演示和可运行命令必须真能用。
D19：在准备好回复技术问题的时段提交一次合规 Show HN；不组织投票、不索要点赞、不多账号互动。
D20：回复反馈并明确哪些是尚未实现的功能，避免为获得关注虚报银行/行情集成。
D21：记录最强信号：有人复跑、导入匿名自制案例、提交 PR，或主动要求更新提醒。

## 第 4 周：判断下一个版本，仍不急着 SaaS

D22：将出现频率最高的需求聚类：导入、现金流计划、所有权归属、界面、数据源、定期更新。
D23：选一个阻碍复用的问题，不同时做全部资产 API。
D24：和愿意继续参与的用户讨论他们上次实际使用的场景，而不是只问“你愿不愿付费”。
D25：做一个可交付的 v0.2.x 改进，补测试和前后对比。
D26：发布改进日志，并归功于真实贡献者；先获得展示名称/引用的同意。
D27：整理自己的技术文章和 CV 项目表述，连接工程事实与 Asset Management 背景。
D28：核对成本：维护、模型费用、数据权利和用户支持，不要只计算服务器。
D29：只有反复要求协作/托管且愿意接受实际试点条件时，提出有限的付费托管试验。
D30：决定继续、收窄或暂缓。将数据写入 `metrics.csv`，保留没有成功的结果。

## 衡量方式

本地工具不偷偷上报使用。可以人工记录自愿反馈，或以后做明确 opt-in 的匿名事件。
`demo_completed` 只在用户实际完成时计数；`repeat_use` 需第二次真实使用；一名用户的重复事件不要当新人。
Star、浏览和下载是辅助关注指标，不是收入或资产管理规模。不要用假 AUM 装点首页。

Hosted 的讨论门槛是反复使用、明确的协作/持续维护需求、可承受的数据/模型成本和实际付费验证。
即使开源免费，提供个性化金融产品建议也不因名称或免责声明自动免于监管；上线边界须实质设计。
