# Review decisions and update household memory

Read `AGENTS.md` first. Canonical workflow; do not duplicate its business rules in runtime adapters.


## Inputs
A previously adopted policy/decision record, the exact earlier model, and selected new evidence.
No autonomous background monitoring is implemented. This workflow runs when invoked.

## Procedure
1. Read the earlier assumptions before reviewing outcomes. Do not retrospectively rewrite the original thesis.
2. Identify facts that changed: ownership, cashflow, debt, liquidity needs, valuations or user goals.
3. Re-run the same deterministic outputs and describe comparable deltas. Keep the same currency/date conventions.
4. Distinguish a wrong assumption, missing evidence, model limitation, changed circumstance and execution difference.
   One favourable outcome does not prove skill; one adverse outcome does not establish a bad process.
5. Record new constraints and decisions as a fresh version. Ask for adoption before replacing an active policy.
6. Log model version, input/output paths and evidence identifiers. This is a transparent local history,
   not a tamper-proof institutional audit trail.

## Output
Use `templates/decision-record.md`: expected versus observed, changed facts, unresolved items and adopted decisions.
No secrets or real family figures belong in public issue reports or discussion threads.
